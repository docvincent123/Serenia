# Lemvori Care Admin — Qt Native · запуск, адміністрування і документи

## 1. Перший запуск та активація

Програма Qt Native входить через HTTPS API; вона не зберігає приватний ключ видавця й не створює ліцензії самостійно.

1. Створіть / перевірте базу `lemvori_core` і встановіть C++ API командою `sudo bash deploy/lemvori-care/install.sh`.
2. На Linux-сервері зареєструйте **публічний** ключ Ed25519 із Lemvori Control:
   `sudo lemvori-carectl publisher-key /path/to/publisher-public.pem`.
   Приватний ключ видавця має залишатися лише в Lemvori Control.
3. Підключіть Qt Admin до `https://localhost:8443` та ввійдіть першим адміністратором.
4. Коли сервер повідомить `activation_required`, з’явиться повноекранний майстер ліцензії з 64-символьним ID сервера.
5. Збережіть запит на ліцензію; видайте через Lemvori Control підписаний документ **саме для цього ID**.
6. Виберіть файл `.lemvori-license` / `.json` або вставте весь підписаний JSON у майстер.
7. Підпис перевіряє API. Активна ліцензія зберігається в PostgreSQL; повторних активацій при перезапуску немає, поки ліцензія чинна.

Важливо: нова порожня БД створює новий server_id. Старий підписаний файл ліцензії до неї не підійде — потрібен новий документ від видавця. Не вимикайте перевірку підпису чи TLS.

## 2. Адміністрування

- **Огляд:** головні дії, назва центру та стан ліцензії.
- **Центр:** профіль і реквізити, назва, контакти, налаштування підключення, модулі та ліцензія.
- **Персонал:** працівники, ролі, обмеження прав, напрямки та кабінети.
- **Робочі процеси:** календар і правила запису, доступ реєстратури, електронне табло.
- **Документи:** затверджені тексти згод, шаблони й PDF-бланки для підписів.
- **Безпека:** сеанси пристроїв, аудит і обслуговування PostgreSQL.

Назва центру показується в заголовку програм після входу. На новій БД першу назву можна заповнити за підписаною ліцензією; адміністратор може налаштувати профіль центру.

## 3. Десять PDF-бланків

Адміністрування → Документи → **Бланки й підписи**:

1. Заява на отримання послуг
2. Інформована згода
3. Обробка персональних даних
4. Правила центру
5. Сімейна згода
6. Направлення до спеціаліста
7. Лист відвідування
8. Підтвердження консультації
9. Заява про відмову
10. Акт передачі зміни

Згенеровані PDF містять назву й реквізити центру та місця для ПІБ, дати й підписів. Згоди беруться **тільки з чинних затверджених шаблонів**. Загальний друк бланка не замінює спеціальну реєстраційну згоду зі зв’язаним ідентифікатором та збереженим сканом.

## 4. Резервні копії й безпека

```bash
sudo lemvori-carectl status
sudo lemvori-carectl backup
sudo lemvori-carectl health
```

Бекапи зберігаються як root-only файли в `/var/backups/lemvori-care`.
**Автоматичне відновлення БД через Qt Admin наразі вимкнене:** старий виклик SOLVIA міг би працювати не з тією БД. Перш ніж використовувати з реальними даними пацієнтів, треба реалізувати перевірене ізольоване відновлення, автоматичне резервування з шифруванням та політику захисту персональних даних.

## 5. Збірка після оновлення

Після оновлення репозиторію збирайте Qt з `native/linux/build-native.sh`. Серверний інсталятор **не встановлює Qt-клієнт** — окремий збірковий артефакт Qt потрібно оновити через GitHub Actions. Код PR не встановлюється на Linux автоматично.
