# Lemvori Care Admin — Qt Native · запуск, адміністрування і документи

## 1. Перший запуск та активація

Програма Qt Native входить через HTTPS API; вона не зберігає приватний ключ видавця й не створює ліцензії самостійно.

1. Із кореня репозиторію на Linux-сервері запустіть `sudo bash deploy/lemvori-care/install.sh`. На чистій системі інсталятор встановить PostgreSQL, створить локальну базу `lemvori_core` і роль `lemvori_app` та попросить логін, ім’я й пароль першого адміністратора. Якщо роль уже існує, а файлу `/etc/lemvori-care/pgpass` немає, введіть її поточний пароль. Повторний запуск зберігає наявні облікові записи, ліцензію та профіль закладу.
2. На Linux-сервері зареєструйте **публічний** ключ Ed25519 із Lemvori Control:
   `sudo lemvori-carectl publisher-key /path/to/publisher-public.pem`.
   Приватний ключ видавця має залишатися лише в Lemvori Control.
3. Встановіть окремий пакет Qt Native з успішної збірки «Lemvori Care native desktop» для цієї гілки. На сервері підключіть Lemvori Care Admin до `https://localhost:8443` та ввійдіть першим адміністратором. На іншому ПК використайте адресу з `sudo lemvori-carectl address` та сертифікат CA саме цього сервера.
4. Коли сервер повідомить `activation_required`, з’явиться повноекранний майстер ліцензії з 64-символьним ID сервера.
5. Збережіть запит на ліцензію; видайте через Lemvori Control підписаний документ **саме для цього ID**.
6. Виберіть файл `.lemvori-license` / `.json` або вставте весь підписаний JSON у майстер.
7. Підпис перевіряє API. Активна ліцензія зберігається в PostgreSQL; повторних активацій при перезапуску немає, поки ліцензія чинна.

Важливо: нова порожня БД створює новий server_id. Старий підписаний файл ліцензії до неї не підійде — потрібен новий документ від видавця. Не вимикайте перевірку підпису чи TLS.

## 2. Адміністрування

- **Огляд:** головні дії, назва центру та стан ліцензії.
- **Центр:** профіль і реквізити, назва, контакти, налаштування підключення, модулі та ліцензія.
- **Персонал:** працівники, ролі, обмеження прав, напрямки та кабінети.
- **Робочі процеси:** календар і правила запису, доступ реєстратури, електронне табло.
- **Документи:** затверджені тексти згод, шаблони й PDF-бланки для підписів.
- **Безпека:** сеанси пристроїв, аудит і обслуговування PostgreSQL.

Після активації відкрийте **Адміністрування → Профіль закладу → Редагувати**. Для лікарні вкажіть її офіційну назву, тип «Лікарня» і назву відділення, наприклад «Відділення психології». У полі «Основний напрямок роботи» виберіть «Психологічне консультування». Для самостійного закладу доступні типи «Психологічний центр» та «Реабілітаційний центр». Перелік напрямків редагується в розділі **Персонал → Напрямки роботи**. Ролі для реєстратури, психолога й керівника задаються в картці працівника.

Для пілоту створіть тестові облікові записи й синтетичного пацієнта. Пройдіть ланцюжок запису, консультації та перегляду звіту під відповідними ролями. Потім створіть копію PostgreSQL і перевірте відновлення на тестовій системі.

## 3. Десять PDF-бланків

Адміністрування → Документи → **Бланки й підписи**:

1. Заява на отримання послуг
2. Інформована згода
3. Обробка персональних даних
4. Правила центру
5. Сімейна згода
6. Направлення до спеціаліста
7. Лист відвідування
8. Підтвердження консультації
9. Заява про відмову
10. Акт передачі зміни

Згенеровані PDF містять назву й реквізити центру та місця для ПІБ, дати й підписів. Згоди беруться **тільки з чинних затверджених шаблонів**. Загальний друк бланка не замінює спеціальну реєстраційну згоду зі зв’язаним ідентифікатором та збереженим сканом.

## 4. Резервні копії й безпека

```bash
sudo lemvori-carectl status
sudo lemvori-carectl backup
sudo lemvori-carectl health
```

Бекапи зберігаються як root-only файли в `/var/backups/lemvori-care`.
Щоденну копію запускає `lemvori-care-backup.timer` о 00:00 за Києвом. Відновлення доступне в Qt Admin на Linux-сервері через **База й копії**. Нові копії та копії перед відновленням шифруються в `.dump.age`. Збережіть окрему захищену копію локального ключа `/etc/lemvori-care/backup.agekey`. Для PostgreSQL на сервері застосовується [окреме налаштування LUKS](../deployment/README.md). Умови роботи з даними пацієнтів і процедура приймання описані в [перевірці перед запуском](LEMVORI-CARE-QA-RELEASE.md).

## 5. Збірка після оновлення

Після оновлення репозиторію збирайте Qt з `native/linux/build-native.sh`. Серверний інсталятор **не встановлює Qt-клієнт** — окремий збірковий артефакт Qt потрібно оновити через GitHub Actions. Код PR не встановлюється на Linux автоматично.

## Підготовка адміністратора через Lemvori Control

На новому сервері команда `sudo bash deploy/lemvori-care/install.sh --prepare-center`
підготує PostgreSQL і покаже ID порожньої інсталяції. У Lemvori Control укажіть цей
ID, виберіть ключ видавця і натисніть **Підготувати першого адміністратора**.
Уведіть ім’я, логін і пароль. Файл `.lemvori-admin` містить підписані дані та
солений перевірник пароля. Він призначений для конкретної порожньої бази і діє
24 години. Файл підписаної ліцензії `.lemvori-license` видається тим самим ключем.

Звірте SHA-256 публічного ключа з видавцем. Подивитися відбиток можна командою
`bash deploy/lemvori-care/install-publisher-key.sh --check publisher-public.pem`.
Потім завершіть встановлення:

```bash
sudo bash deploy/lemvori-care/install.sh --admin-setup first.lemvori-admin publisher-public.pem SHA256
```

Увійдіть у **Lemvori Care Admin** обраним обліковим записом та імпортуйте ліцензію.
Захищені операції перевіряють підпис, ID сервера, строк дії та доступність модулів.

## Робочі місця й архіви

Реєстратура працює у **Lemvori Care**, адміністратор у **Lemvori Care Admin**.
Для клінічного працівника вкажіть посаду й напрямок. На його ПК скопіюйте
**Код цього ПК** перед входом. У картці працівника ввімкніть
**Робота з призначеного ПК** та вставте код. Вимкнення або зміна прив’язки завершує
поточні сеанси працівника. Клінічний працівник бачить лише власні прийоми
й записи у своєму архіві зміни.

Загальний архів карток доступний адміністратору. **Архів зміни** відображає
проведені консультації за обрану дату з даними пацієнта, часом і відповідальним
працівником. Для медичного директора дозвіл **Доступ до архіву консультацій за зміну**
задається в картці його облікового запису.

## Заяви з картки пацієнта

У картці відкрийте **Заяви**, виберіть активний напрямок закладу й натисніть
**Створити заяву**. Сервер присвоїть номер `LC-ZV-РІК-НОМЕР`, збереже заяву
в картці й зафіксує реквізити та назву напрямку на момент її створення.
Кнопки **PDF** і **Роздрукувати** працюють із тим самим збереженим документом.

Це внутрішня форма звернення для надання послуг. Заклад затверджує власну
форму та окремо визначає, коли застосовуються інформована згода, представництво,
офіційні форми меддокументації й обробка персональних даних. Нормативні джерела:

- [Закон № 2297-VI «Про захист персональних даних»](https://zakon.rada.gov.ua/laws/show/2297-17#Text)
- [Основи законодавства України про охорону здоров’я № 2801-XII](https://zakon.rada.gov.ua/laws/show/2801-12#Text)
- [Закон № 4223-IX «Про систему охорони психічного здоров’я в Україні»](https://zakon.rada.gov.ua/laws/show/4223-20#Text)
- [Інструкція МОЗ щодо форми № 025/о](https://zakon.rada.gov.ua/laws/show/z0669-12#Text)
