## Дороблені сценарії

- Лист очікування шукає активних пацієнтів на сервері сторінками по 10. Вибраний пацієнт залишається при переході між сторінками/пошуковими запитами. Повний реєстр пацієнтів не завантажується. Помилка отримання черги не залишає доступними старі дії й не видається за порожню чергу.
- Цілі реабілітації: авторські ключі повторення захищають створення й прогрес від дублювання після втрати відповіді. Квитанції і запис зберігаються в одній транзакції; між API-процесами використовується transaction-scoped advisory lock. Повтор ключа з іншим вмістом повертає 409.
- Конкурентне оновлення цілі перевіряє фактично змінений SQL-рядок. Застарілий запит не додає помилковий запис історії. Після 409 психолог може явно оновити дані цілі; введений текст залишається у формі. Повтор після втрати відповіді повторює той самий ключ.
- Форми блокуються під час запису; подвійне надсилання не породжує нову операцію. Після помилки завантаження плану старі дії приховуються.

## Сумісність встановлених центрів

Це перейменування компанії, а не створення іншої програми. Залишені стабільними Android package/application ID `com.quremed.solvia`, формат профілю `quremed.solvia.mobile`, формат ліцензії, Inno AppId, серверні каталоги ProgramData та каталог WebView2. Їх довільне перейменування зробило б APK іншою програмою або відокремило б чинні дані/підключення. Це технічні ідентифікатори, не назва видавця в інтерфейсі.

Qt зчитує старі `QureMed/SOLVIA` налаштування лише якщо нове підключення LemvoriLab ще відсутнє. Уже налаштована нова адреса не перезаписується. Збережені URL і pinned server identity перевіряє окремий запуск справжньої Qt-програми в CI.

Експорт сертифіката отримав ім’я `LemvoriLab-Local-CA.crt`; старий файл CA залишається джерелом сумісності. Linux створює посилання, Windows копіює той самий публічний сертифікат під двома іменами. Наявний CA, приватні ключі та відбиток довіри через зміну назви не перевипускаються. Старі сертифікати залишаються чинними.

## Перевірки та встановлення

Локально: production React/Vite і C++ збірки; CTest (інтеграція PostgreSQL 17, ліцензії, continuity); 27 інтеграційних сценаріїв, включно з двома API-процесами; браузерні перевірки ролей, логіну, запису, календаря, цілей, сімей, архіву, черги, документів/друку, PC update, TV, recovery та сповіщень; Python/shell перевірки та зворотне оновлення Linux UI. Синтетичні дані, не клінічні дані центру.

CI на push додатково збирає Windows/Linux інсталятори, Android і Qt .deb. Фізичні ПК/Android/TV, принтер і LAN центру не перевірені в хмарі. Нативний Qt залишається окремим preview, а не повною заміною всіх React-модулів. Підписаний Android release можливий лише якщо в GitHub уже налаштовані постійні signing secrets; тестовий APK не оновлює production.

Оновити сервер і клієнти разом після перевіреної резервної копії. Нові таблиці створюються при запуску; видалення пацієнтів або старих таблиць немає. Це перевірений набір конкретних доробок, без твердження про відсутність усіх можливих помилок чи вже виконане встановлення в центрі.
