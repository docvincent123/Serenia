# Проблемні записи телефона: обробка на ПК

У «Пристроях» біля проблемного телефона адміністратор натискає **«Проблемні записи»**. Відкривається список із пацієнтом, причиною помилки та станом обробки. Запис містить початковий текст телефона, актуальну серверну чернетку та наявні консультації цього прийому.

- **Провести консультацію**: перевірити/виправити текст, тривалість, тип і ризик; указати причину та підтвердити, що консультація фактично відбулася. Відмінна серверна чернетка потребує окремого підтвердження. Зберігаються початковий текст і знімок серверної чернетки; автор консультації — початковий психолог, у журналі дія належить адміністратору.
- **Підтвердити проведену №…**: звірити з наявною консультацією. Її текст залишається без змін, повторна консультація не створюється. Новий запис не можна провести, коли консультація цього пацієнта в цьому прийомі вже існує.
- **Відновлення неявки / скасування** потребує окремого підтвердження. Для групи змінюється лише потрібний учасник; консультації інших зберігаються. Помилка перевірки тексту відкочує також відновлення статусу в тій самій транзакції.
- Майбутню консультацію провести не можна. Психолог має бути активним та залишатися призначеним пацієнту. Зміна автора, пацієнта або прийому через форму відновлення заборонена.
- Версії джерела й серверної чернетки перевіряються під час збереження. При конфлікті введений текст лишається у формі до явного перезавантаження. Чернетка іншого, новішого прийому не видаляється.

## Телефон

Потрібна **SOLVIA Android 3.3.4 (код 41)** разом із цим сервером/ПК. Телефон передає резервні знімки проблемних записів через окремий автентифікований API, не в моніторингових лічильниках. Доступ до змісту на ПК має лише адміністратор. Інші психологи, реєстратура та керівник не отримують ці тексти.

Після обробки на ПК наступна синхронізація телефона звіряє результат із ключем, пацієнтом, прийомом і початковим текстом. Завершений запис лишається зашифрованим у локальному журналі. Лише незмінену відповідну чернетку можна прибрати; нові локальні правки лишаються для звірки та уточнення. Стан телефона не обнуляється на ПК штучно: лічильники оновлює сам телефон після підтвердження.

На старій версії 3.3.2 зі скриншота сервер має тільки кількість проблем. Новий ПК пояснює необхідність оновити телефон і виконати синхронізацію; він не імітує проведення без клінічного тексту. Якщо телефона немає в мережі, резервний знімок ще не може надійти. Звичайне передавання не блокується, якщо API відновлення тимчасово недоступне або сервер ще старий.

Однаковий запис у черзі й чернетці рахується один раз. Окремі новіші правки лишаються видимою проблемою.

## Реалізація й перевірки

Міграція додає таблицю mobile_recovery та індекс без видалення наявних даних. POST /api/mobile-recovery прив’язує джерело до пристрою авторизованої сесії та перевіряє авторство прийому; резервні знімки передаються партіями до п’яти. /api/admin/recovery та /api/admin/recovery/:id доступні лише адміністратору. Джерело після обробки незмінне; причина, виконавець, кінцевий текст та серверний знімок зберігаються окремо.

Спільна функція збереження консультації використовується звичайним телефоном і відновленням, з однаковими клінічними перевірками та завершенням груп. Відновлення має окрему перевірку наявного запису й не обходить перевірку призначеного психолога.

Локально: production React build, браузерний device-recovery (проведення, подвійне натискання, збереження тексту при 409, явне перезавантаження, звірка без дубля, старий телефон, компактний екран), C++ syntax check. PostgreSQL integration доповнений правами, версіями, збереженням джерел, авторством, відновленням неявки/групи, відкотом помилки, захистом новішої чернетки та майбутніх прийомів. RecoverySyncTest перевіряє локальне шифроване відновлення, збереження новіших правок, недоступність API, розбиття запитів і лічильники. Підтвердження PostgreSQL та Android збірки/емулятора — GitHub Actions; фізичний телефон потребує приймання. Встановлювати тестовий APK поверх робочого com.quremed.solvia не можна: потрібен робочий APK із тим самим постійним сертифікатом.
