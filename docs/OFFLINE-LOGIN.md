# Екран входу та один активний сеанс

Windows завантажує екран входу з локальної папки `ui`. Linux GTK/WebKit тепер теж завантажує встановлений локальний інтерфейс через `solvia://app`, а API викликає за HTTPS-адресою центру. Сервер не потрібен для відкриття форми входу. На Linux потрібно оновити повний пакет клієнта (скрипт і `ui`), на Windows — папку `ui` із відповідної збірки.

При відсутності зв’язку форма показує: «Сервер недоступний. Зверніться до системного адміністратора.». Перевірка повторюється через 5 секунд після завершення попереднього запиту. Після відновлення сервера працівник може ввійти в тому самому вікні. Паролі у фонових перевірках не передаються. Якщо в цьому вікні вже був збережений чинний токен, відсутність мережі не стирає його: після відновлення API програма перевіряє та відновлює саме цей сеанс. Токен видаляється лише після явної відповіді 401.

## Захист від дублів

Один обліковий запис має один активний сеанс на всіх ПК і телефонах. Старий сеанс продовжує працювати. Новий вхід після правильної перевірки пароля отримує HTTP 409 без токена: «Цей обліковий запис уже використовується на іншому пристрої. Спочатку завершіть попередній сеанс або зверніться до системного адміністратора.».

Для перенесення роботи натисніть «Вийти» на першому пристрої. Якщо він недоступний, адміністратор завершує його сеанс у наявному списку сеансів. Закриття вікна без «Вийти» не звільняє чинний серверний сеанс. Прострочений звичайний сеанс або сеанс закритої зміни не блокує новий вхід; Android-сеанс відкритої зміни зберігає попередню політику тривалості.

Під час оновлення з наявних дублів зберігається найраніший активний сеанс (за `created`, а при однаковій секунді — стабільно за токеном). Унікальний індекс `sessions(user_id)` та блокування рядка користувача не дозволяють двом одночасним входам створити дубль. Відхилений вхід не змінює токен попереднього пристрою. Клінічні дані, чернетки та прив’язки телефонів до зміни не видаляються.

Linux CORS дозволяє лише окремий локальний origin `solvia://app` на додаток до Windows `https://app.solvia.invalid`; TLS-перевірка API зберігається. Локальний обробник видає тільки файли встановленої папки UI та відхиляє вихід за її межі, включно із symlink.

Перевірки: `tests/offline-login.mjs`, `tests/linux-client.py`, `tests/linux-native-ui.py` та сценарій `test_b_single_session_across_devices` у PostgreSQL integration suite.
