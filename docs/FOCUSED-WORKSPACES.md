# SOLVIA: зосереджені робочі місця (UX після 3.1)

## Мета
Зменшити перевантаження адміністратора та реєстратури **без видалення функцій, зміни ролей, API, таблиць PostgreSQL чи медичних даних**. Це окремий шар компонування клієнта поверх SOLVIA 3.1.

## Адміністратор
- Постійно видно чотири основні розділи: **Огляд центру, Прийоми за зміну, Календар, Пацієнти**.
- Усі інші наявні розділи згруповані у згорнуті блоки; доступний каталог **Усі розділи**.
- Налаштування центру і профіль залишаються у нижньому блоці меню, а не губляться у списку.
- Огляд прибирає великий декоративний банер на користь двох конкретних дій, показників періоду та перегляду стану реєстратури. Інформація про БД, резервні копії та пристрої доступна за розгортанням.
- Дзвіночок робочих подій, системні повідомлення, права та журнал дій залишаються без змін.
- Додана згорнута за замовчуванням стрічка останніх п'яти подій; відкриття вмикає оновлення кожні 15 секунд, без імен пацієнтів чи клінічного тексту. Дані надходять з того самого серверного API з перевіркою ролі.

## Реєстратура
- Постійний короткий шлях: **Прийоми за зміну, Календар, Пацієнти**. Інші інструменти у групах.
- На сторінці зміни першочергові дії — **Зареєструвати пацієнта** та **Записати на прийом** (поточні кнопки «+ Новий пацієнт» і «+ Записати на прийом»).
- Три показники: очікуємо прибуття, у центрі/на консультації, проконсультовано. «Не проведені» доступні окремою вкладкою.
- Пошук за ПІБ/номером/телефоном видно постійно; дата й психолог сховані за кнопкою **Дата і психолог**, після фільтрування є позначка «Застосовано».
- У вибраному прийомі спочатку показані основні дії залежно від стану: прибуття, виклик на TV, перенесення, картка пацієнта. Контакти, категорія та часовий аудит розкриваються окремо; неявка/скасування залишаються в окремому розгортанні.
- Календар доступний однією кнопкою головного меню і у додаткових фільтрах.

## Безпека та сумісність
- Права не виводяться з видимості меню: усі серверні перевірки залишаються обов'язковими.
- Права на перегляд ПІБ і консультацій, TV pairing, зашифровані офлайн-чернетки та захист від повторного збереження не змінені.
- Старий сервер і схема PostgreSQL не модифікуються цими UX-правками, але застосунок потребує сумісної збірки SOLVIA 3.1.
- Розділи приховані лише за групуванням, **не видалені**. Каталог модулів дає доступ до повного набору функцій відповідної ролі.
- Адаптивні стилі призначені для Windows WebView2, Linux GTK/WebKit і браузера у вузькому вікні; фізичне тестування робочих пристроїв ще потрібне.

## Перевірка
- `node tests/motion-workspace.mjs` — повнота модулів кожної ролі та календарні сценарії.
- `npm --prefix frontend ci && npm --prefix frontend run build` — React production build.
- `node tests/ui-regression.mjs` — Playwright, після створення `frontend/dist`: компактне меню, згортання фільтрів, прибуття, перенесення, архів, доступність налаштувань та ролей.
- Повний CI: Windows installer/PostgreSQL, Linux GTK/WebKit, Android regression. Android у цій UX-гілці не змінюється.

Розгортання в реальному центрі, підпис виробничої APK та тест фізичного TV/принтерів не входять до цього PR.
