# SOLVIA Табло для Smart TV — 3.0

Вебсторінка, яку віддає сервер SOLVIA. Працює в Chrome телевізора в локальній мережі;
додаткова база даних, хмарний сервер або інтернет для роботи не потрібні.

## Перший запуск

1. Установіть сервер і Server Console зі збірки цієї гілки. Пакет UI містить tv/index.html.
2. У Server Console відкрийте розділ **TV-табло**. Там показано адресу сервера з /tv.
3. На Smart TV відкрийте цю адресу в Chrome, наприклад https://192.168.1.10:8443/tv.
   Телевізор має бути в мережі центру та довіряти сертифікату сервера, як інші клієнти.
4. На телевізорі натисніть **Отримати код підключення**.
5. Введіть 6 цифр у Server Console, задайте назву телевізора, кабінет або всі кабінети,
   формат ПІБ, час сторінки та новини. Натисніть **Підключити табло**.
6. На TV з'явиться розклад. Кнопка ⛶ вмикає повний екран, якщо браузер це підтримує.

Код підключення діє 10 хвилин і використовується один раз. Ключ пристрою зберігається
у локальному сховищі Chrome, не в URL. Після перезапуску браузера табло підключається
повторно без логіна працівника. Очищення даних браузера потребує нового підключення.
Автозапуск Chrome після ввімкнення конкретної моделі телевізора налаштовується окремо.

## Що на екрані

- Назва центру, дата та годинник за локальним часом сервера; часовий пояс телевізора не впливає.
- Час прийому, ПІБ пацієнта, психолог, кабінет та статус: заплановано, прибув, запрошуємо, на консультації.
- Сьогоднішні незавершені прийоми; завершені, скасовані, неявки та чернетки виключаються.
- Автоматична зміна сторінок (6–60 секунд) та адаптація кількості рядків до висоти вікна.
- Анімований поточний виклик, який явно запускає працівник.
- Рухома стрічка **Новини центру** внизу. Новини вводить адміністратор у Server Console:
  кожне оголошення з нового рядка. Це внутрішні оголошення центру, без зовнішнього новинного сервісу.

Розклад і новини запитуються кожні 5 секунд. При втраті мережі старі ПІБ прибираються;
після відновлення сторінка підключається автоматично. Опівночі попередній розклад
приховується до отримання нового. Reduced-motion налаштування браузера вимикає анімації.

## Виклик

У головній програмі адміністратора, реєстратури й психолога є розділ **TV-виклики**.
Психолог бачить лише свої записи. Спочатку відмітьте прибуття в звичайному робочому процесі.
Потім **Запросити** показує виклик на 2 хвилини. Можна повторити або прибрати виклик.
Початок/завершення консультації автоматично прибирає відповідне запрошення з екрана.
Поточний час запису сам по собі не викликає пацієнта. Доступ реєстратури й відкрита зміна
перевіряються сервером як у звичайній програмі.

## API та доступ

- POST /api/tv/pair — створити код і секрет пристрою (обмеження частоти).
- GET /api/tv/pairing — перевірити схвалення коду.
- GET /api/tv/schedule — мінімальний розклад і налаштування табло.
- GET/POST /api/admin/tv-displays — список і схвалення пристрою (тільки адміністратор).
- PATCH/DELETE /api/admin/tv-displays/:id — налаштування, пауза або відкликання доступу.
- GET /api/tv/candidates, POST/DELETE /api/tv/call — робота з викликами.

TV-запити передають Authorization: Bearer <device-token>. Ключі TV не створюють сеансів
працівників і не дають доступу до інших API. Сервер зберігає тільки SHA-256 секрету.
Табло не отримує телефонів, категорій пацієнтів, діагнозів або клінічних нотаток.
Формат імен: повне ПІБ або прізвище з ініціалами. Повний ПІБ увімкнений за замовчуванням.
Нові таблиці tv_displays, tv_pairings і tv_calls створюються автоматично при старті сервера.

## Перевірка

Локальні перевірки: production-збірка обох сторінок, C++ syntax-only, тести пагінації,
черги викликів і переходу годинника через північ. Додані integration-тести реального
PostgreSQL API та Playwright сценарій 720p/1080p: pairing, виклик, стрічка новин,
пагінація, збій мережі, повторне підключення й відкликання доступу. Ці повні перевірки
виконуються в CI; конкретний телевізор слід перевірити після встановлення.

## Окремий сайт на Netlify

Статичний сайт можна опублікувати на власному домені Netlify. На сервері SOLVIA
задайте SOLVIA_TV_SITE_ORIGIN точною адресою сайту (HTTPS origin, без шляху
й кінцевого /), наприклад https://solvia-tv-example.netlify.app. Для Linux додайте
цей параметр у /etc/solvia/server.env та перезапустіть sudo systemctl restart solvia.
Потрібна збірка сервера з підтримкою цього параметра. Дозвіл застосовується тільки
до TV pair/pairing/schedule; API працівників залишається закритим для цього origin.
Адреси випадкових preview-деплоїв не отримують дозволу автоматично.
