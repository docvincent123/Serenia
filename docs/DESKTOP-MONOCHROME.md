# SOLVIA: біло-чорний простір ПК

Основа: feature/desktop-yellow-role-access, b2a1b8d. Це продовження актуального ПК, а не раннього main. Нативний Android та схема БД не змінені.

Графітове меню, білі робочі поверхні, чорні основні дії, нейтральні картки й поля. Усі модулі й розмежування ролей збережені: кабінети, сім’ї, календар, команда, виписки, аналітика, повідомлення, архів та налаштування. Вхід і профіль оформлені в тій самій палітрі. Помилки мають окремий акцент і текст; стан мережі залишається видимим. Немає нових шрифтів із мережі, залежностей чи важких ефектів.

## Щоденна робота

Адміністратор через «Керувати доступом» надає реєстратурі дозвіл на дату й час. Це вже реалізований серверний дозвіл попередньої гілки: він не завершує клінічну зміну й не виходить із телефонів психологів. У календарі та формі запису можна обирати дату й довільні хвилини; конфлікти перевіряє сервер. Виписки редагуються з причиною, історією та контролем версії.

Нова кнопка «Підсумок дня» доступна адміністратору й допущеній реєстратурі в смузі відкритої зміни. Звіт завантажує операційний список /api/shift-workspace за обрану дату: загальна кількість участей, завершені, незавершені, непроведені, підсумок по психологах та список прийомів. Кожен учасник групи рахується окремо. Клінічні нотатки не запитуються. Порожній день, завантаження й помилка відрізняються; є повтор. Запізніла відповідь попередньої дати ігнорується. Звіт — поточний стан на момент завантаження, а не збережений незмінний знімок. Для архівного примірника є «Друк / PDF». Звіти психологів у їхньому окремому розділі зберігаються як раніше.

## Перевірка

Production React build пройшла. Node-тести auth-session, backup-status, booking, connection, drafts, performance та shift-workspace пройшли. Браузерні desktop-system та ui-regression пройшли на фактичному production-бандлі із синтетичними API: чотири ролі, щоденний дозвіл, запис, виписки, компактний екран, профіль, звіт психолога, новий операційний звіт і друк без меню. Скриншоти входу, огляду та реєстратури перевірені візуально.

Ці локальні перевірки не є запуском Windows EXE або перевіркою живої PostgreSQL. Збірку інсталяторів і серверні інтеграційні тести треба підтвердити в CI перед встановленням. Гілка не зливається й не розгортається цим оновленням.
