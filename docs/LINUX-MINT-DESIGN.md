# SOLVIA 3.0 — Linux Mint Design

Дизайн моушн-презентації перенесено у справжній React-інтерфейс Linux-клієнта: темна зелена панель, м’ятні акценти, теплий світлий фон, картки, календар, таблиці, форми й вікна. Оновлено також кольори нативної GTK-шапки та Server Console. Режим для слабких Linux-ПК і налаштування зменшення руху збережено.

Код базується на гілці `feature/center-connection` репозиторію `docvincent123/Serenia`, а не на старому Win32 MVP у `main`. Спільний React-інтерфейс застосовується також у Windows WebView2-клієнті цієї гілки. Android має окремий Kotlin-інтерфейс і тут не змінювався.

## Встановлення оновлення дизайну

Пакет призначений для **вже встановленої Linux SOLVIA 3.0.0**. Це оновлення інтерфейсу, воно не містить сервера PostgreSQL або нової схеми БД. Версія перевіряється до заміни файлів; для непідтвердженої або старішої версії зміни не застосовуються.

1. Закрийте вікна SOLVIA та Server Console.
2. Розпакуйте завантажений пакет і виконайте:

```bash
tar -xzf SOLVIA-3.0.0-Linux-Mint-UI.tar.gz
cd SOLVIA-Linux-Mint-UI
sudo python3 update-ui.py
```

3. Знову відкрийте SOLVIA звичайним ярликом.

Оновлювач перевіряє контрольні суми, створює копії наявного інтерфейсу й замінює лише `ui` у наявних каталогах `/opt/solvia` та `/usr/local/lib/solvia`, а також GTK-оболонку `/usr/local/lib/solvia/solvia-linux-app.py`, якщо вона встановлена. Старі каталоги залишаються поруч під іменами `ui.before-mint-ДАТА-ID`; попередня оболонка — `solvia-linux-app.py.before-mint-ДАТА-ID`. При помилці під час застосування попередні файли відновлюються. Після успішного завершення шляхи копій показуються в терміналі.

PostgreSQL, пацієнти, облікові записи, сертифікати, налаштування сервера та systemd-служби оновлювач не змінює й не перезапускає. Старі кешовані офлайн-дані застосунку зберігаються.

## Перевірка

Збірка: `npm --prefix frontend ci && npm --prefix frontend run build`.

Перевірки: `tests/desktop-system.mjs`, `tests/ui-regression.mjs`, `tests/linux-client.py`, `tests/mint-ui-update.py`. Перевіряються ролі, календар, форми, зміни, чернетки, повторна доставка консультації, вузькі вікна, збереження даних під час оновлення, відмова для пошкодженого пакета й невідповідної версії. Скриншоти використовують лише синтетичні дані.

Нативне GTK/WebKit-вікно перевіряється окремим наявним `tests/linux-native-ui.py` у повному Linux-конвеєрі. Локальні браузерні перевірки самі по собі не є перевіркою GTK-вікна.
