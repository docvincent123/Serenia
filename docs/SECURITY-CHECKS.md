# SOLVIA 2.2: перевірки захисту

Це перелік перевірених меж, а не гарантія відсутності всіх вразливостей.

- Авторизація на сервері: підроблений або прострочений Bearer-токен не дає доступу. Паролі хешуються PBKDF2-HMAC-SHA256; токени сесій зберігаються як SHA-256.
- Ролі й підміна ID: інший психолог не читає картку, курси, документи чи направлення чужого пацієнта й не змінює чужу супервізію. Керівник не читає приватні картки; реєстратура не читає консультаційні нотатки. Системні, кадрові та сесійні операції обмежені адміністратором.
- Вхід: невдалі спроби обмежено за фактичною адресою з'єднання й обліковим записом; заголовок X-Forwarded-For не дозволяє обійти ліміт. Ліміт зміни пароля захищає перевірку поточного пароля. Дані лімітера очищаються й обмежені за кількістю ключів. Це ліміт у пам'яті процесу; перезапуск його скидає. За Windows reverse proxy IP-ліміт спільний для клієнтів, а ліміт облікового запису окремий.
- Вхідні дані: SQL-параметри; відхилення NUL у тексті й переповнення числових ідентифікаторів; перевірка base64 і сигнатури PNG/JPEG. Остання не є повним антивірусним або декодерним аналізом зображення.
- HTTPS: зміна LAN IP перевипускає серверний сертифікат тим самим CA. HTTP не може слухати LAN без TLS. Клієнти не відключають перевірку сертифікатів.
- HTTP: обмежений розмір тіла, таймаути, no-store, nosniff, заборона вбудовування у iframe й об'єктів. CSP дозволяє inline CSS для динамічної верстки React, але не inline JavaScript.
- База: PostgreSQL Linux тільки через локальний Unix socket; service-account без superuser. Ключ CA доступний root; ключ TLS — root і групі сервера.

Автотести використовують синтетичні дані й реальний сервер/PostgreSQL. Вони перевіряють також реєстрацію, бронювання/конфлікти, консультації, статистику, курси, документи, направлення, супервізії, закриття зміни та припинення сесій. Linux CI перевіряє відновлення старої адреси й сертифіката після рестарту та перевстановлення, збереження CA і backup/restore/upgrade.

Додаткові production-контролі, яких тут немає: MFA та незалежний penetration test. Налаштування мережі, резервні копії й доступ до фізичного сервера залишаються частиною роботи центру.
