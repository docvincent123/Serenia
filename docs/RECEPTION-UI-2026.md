# SOLVIA / Serenia — робоче місце реєстратури

Стан: оновлення **нативного Windows C++ клієнта** у гілці `feature/solvia-reception-ui-20261105`.

## Внесені зміни

- Єдині кольори: темний графіт навігації, теплий жовтий акцент, світла робоча поверхня для читабельних таблиць.
- Реєстратор після входу переходить на сторінку пацієнтів; її пункт меню називається «Реєстратура».
- Назви розділів і підказки орієнтовані на щоденну роботу, а не загальні маркетингові тексти.
- Пошук по ПІБ/телефону ігнорує регістр українських літер через системну Unicode-функцію Windows.
- Windows UI smoke-test перевіряє вхід ролі «reception», відкриття сторінки пошуку і знаходження синтетичних пацієнтів змішаним регістром.

## Перевірка

1. Зібрати Windows x64 у GitHub Actions і виконати `ctest`.
2. Відкрити отриманий `SOLVIA-0.1.0-Windows-x64` на тестовому ПК.
3. Увійти як `reception` — одразу видно реєстратуру.
4. Перевірити пошук тестових ПІБ у різних регістрах, фільтрацію за телефоном, подвійний клік по картці.
5. Увійти як `psychologist`, `admin`, `director` і пересвідчитися, що права доступу не змінилися.
6. Перевірити інтерфейс за 100% та 125% масштабування екрана.

## Межі роботи

Цей PR покращує **існуючий** клієнт, а не змінює архітектуру даних.

- «Прибув», черга консультацій, визначення психологів на зміні та редагування прийомів потребують розширення серверної моделі.
- **Сканування і прикріплення документів ще не реалізовані у Serenia.** Для цього потрібні авторизовані маршрути для файлів, правила доступу для реєстраторів і психологів, ліміти, аудит, ізольоване зберігання і підтвердження захисту персональних даних. До появи цієї інфраструктури не додавати кнопки, що імітують сканування.
- Сервер у поточному репозиторії використовує SQLite, не PostgreSQL; цей PR не здійснює міграцію БД.
- Автобекапи, відновлення, TLS налаштування і навантажувальний тест на 30–40 одночасних працівників — **окремі невиконані перевірки**. Робочі дані пацієнтів не використовувати для демо або тестів.
