# SOLVIA: React-простір реабілітаційного центру

Основа: актуальна `feature/rehab-center-readiness`, `66852c2` від 30 жовтня 2026. React залишається робочим інтерфейсом; окремий Qt-клієнт у цій зміні не редагувався.

## Завершені сценарії

- Об’єднано `feature/solvia-ops-center-readiness-20261029`: передача організаційних справ між змінами, створення/виконання, пріоритети, історія, аудит, захист від дублювання. Під час відправлення поля блокуються, після помилки завантаження старі дії приховуються.
- Об’єднано `feature/psychologist-live-roster-20261029`: психологи на зміні, доступний/очікує/на консультації, адміністративне призначення, підбір запису за складом зміни. Телефон у мережі не підміняє присутність на зміні.
- Картка → **Прийоми**: наступні та історія, час, кабінет, психолог, стан конкретного учасника. Запис підставляє пацієнта; перенесення використовує спільну форму. Після збереження список оновлюється. Сторінки по 10, помилки й повторне завантаження без старих дій. Інші учасники групи та приватні нотатки не повертаються.
- **Сім’ї**: пошук, кількість учасників, окремий серверний пошук учасників сторінками по 25, роль у сім’ї, стан курсу, перехід у картку. Архівні учасники залишаються у сім’ї. Повний реєстр пацієнтів більше не завантажується для цього розділу.
- **Архів**: серверний пошук і сторінки по 25; помилка не видається за порожній архів. Повторне звернення ведеться через новий курс у наявній картці.
- Новий світлий **логін**: читабельна ілюстрація, великі поля, показ пароля, реальний стан сервера, допомога з доступом, відновлення файла підключення. Короткі вступні анімації вимикаються через reduced motion або полегшений режим. Мобільна версія зосереджена на формі.

## Щоденна робота

| Роль | Сценарій |
| --- | --- |
| Реєстратура | Знайти/зареєструвати → записати → відмітити прибуття → передати незавершені справи |
| Психолог | Мій розклад → картка → консультація/чернетка → цілі та прогрес → звіт |
| Адміністратор | Відкрити зміну/доступ → призначити психологів → прийоми/кабінети/команда → контроль резервування |
| Керівник | Огляд → психологи на зміні → навантаження → супервізії та виписки |

Збережено серверні права ролей, коротке основне меню й каталог «Усі розділи».

## Перевірено

Production-збірки React/Vite та C++; CTest: усі 3 набори, включно з 26 інтеграційними сценаріями на справжньому HTTP API й окремій PostgreSQL 17. Навантаження 40 облікових записів/360 запитів: без помилок і дублів.

Браузерні сценарії: 4 ролі, логін на 5 розмірах екрана/показ пароля/помилка входу/reduced motion, запис/перенесення, прийоми пацієнта, сім’ї, календарні помилки, архів, передача зміни/склад зміни, документи/друк, черги, повідомлення, TV, відновлення пристроїв та оновлення ПК. Браузерні відповіді та скриншоти містять лише синтетичні дані. Моделі запитів, чернеток, підключення та запису також перевірено.

## Встановлення та межі

Оновлювати сервер і React-клієнт разом: потрібні новий маршрут прийомів та фільтр сім’ї. Схема додає таблиці й індекси без видалення даних; перед встановленням потрібна перевірена резервна копія. GitHub Actions збирає Windows/Linux; хмарні перевірки не замінюють приймання на двох реальних ПК центру, фізичних Android/TV і принтері. Див. [CENTER-ACCESS.md](CENTER-ACCESS.md), [LINUX.md](LINUX.md), [OPS-CENTER-IMPLEMENTATION.md](OPS-CENTER-IMPLEMENTATION.md).

Інтеграції ЕСОЗ/HELSI, е-рецепти, платежі й публічний кабінет пацієнта цим етапом не додавалися. Окремий план інфраструктурних робіт описаний в Ops Center. Ця зміна не є підтвердженням розгортання на реальних даних або гарантією відсутності всіх помилок.
