# Lemvori Care Qt Native — інтерфейс і робочі сценарії

## Що додано в PR #42

- **Картка пацієнта**: окремі вкладки «Огляд», «Курси», «Прийоми», «Документи», «Направлення» та доступні тільки адміністратору «План реабілітації», «Консультації».
- **Огляд картки**: контактні дані, джерело звернення, статус активного курсу, статус підписаних згод, кількість документів та адміністративні нотатки лише для адміністратора.
- **Прийоми пацієнта**: майбутні й минулі з реального C++ API `GET /api/patients/:id/appointments`, обов'язкова посторінкова вибірка; перевірка актуальної картки перед показом результатів, щоб відповідь старого запиту не перемішала дані різних пацієнтів.
- **Талон на прийом**: PDF з назвою і контактами центру, ПІБ пацієнта, номером картки, датою й часом найближчого прийому, спеціалістом та кабінетом. Талон не є медичним висновком і не містить клінічних нотаток.
- **Направлення**: відстеження статусу (рекомендовано / направлено / виконано / скасовано) прямо з картки. Зміни проходять через сервер, журнал аудиту й перезавантаження картки. Статус не позначається автоматично без підтвердження.
- **План реабілітації**: читабельні картки клінічних цілей з базовими показниками, цільовими значеннями, прогресом, версією та останніми оновленнями. Редагування залишається за призначеним психологом на Android, згідно із серверними ролями.
- **Реєстрація**: розмітка форм адаптується до ширини екрана, підказки біля телефонного номера й дати народження, перевірка реальної календарної дати та потрібних згод до збереження.
- **Універсальні редактори**: адаптивні 1–2 колонки для направлень, записів у чергу, сімей, супервізій тощо; уніфіковані поля й заголовки з назвою центру.
- **Збереження вигляду**: Qt запам'ятовує положення/розмір вікна окремо для робочої програми й Admin. У цих налаштуваннях не зберігаються токени, паролі чи картки пацієнтів.

## Автоматизоване тестування

`tests/native-qt-workflow.py` — ізольований тестовий HTTPS-центр із синтетичними пацієнтами.
`tests/native-qt-ui.cpp` — справжній нативний Qt-клієнт: відкриття картки, завантаження майбутніх прийомів, перемикання на історію, створення талона PDF, зміна статусу направлення, повернення до огляду, потім старі сценарії реєстрації, сканування, запису та ролей.

`tests/integration.py` окремо перевіряє серверні права й роботу направлень та історії прийомів.
GitHub Actions `Lemvori Care native desktop` збирає Linux і Windows клієнти й запускає тести. **До завершення останнього прогону жодна із цих змін не вважається перевіреною на фізичному Linux/Windows комп'ютері.**

## Обов'язкова ручна приймальна перевірка

1. Підключення на `https://localhost:8443` на серверному ПК й по LAN IP з іншого ПК; сертифікат без обхідних вимкнень TLS.
2. Вхід адміністратора/реєстратора, ліцензія й правильна назва центру.
3. Картка пацієнта, переходи між вкладками та пошук в архіві без затримок, помилок і показу чужих даних.
4. Згоди, підписи, скани, друк талона й бланків на реальному принтері.
5. Запис на прийом, перенесення, неявка, активні курси, направлення, виписка.
6. Перезапуск програми після зміни розміру вікна; коректне відновлення геометрії, особливо після підключення іншого монітора.
7. Відключення Wi-Fi/LAN, повторне підключення, відсутність дублювання даних або зламаних сесій.
8. Резервне копіювання та відновлення тільки на **окремій тестовій БД**, а не на живих картках центру.
9. Права реєстратури: без перегляду клінічних цілей/консультацій, журнал аудиту щодо змін.
10. Реальні робочі зміни психологів на Android, синхронізація, підтвердження доставки повідомлень.

**Примітка:** ця гілка — код у GitHub, а не автоматично встановлена нова версія в центрі. Перед роботою з реальними медичними даними потрібні захист БД, шифровані копії, політика обробки персональних даних, огляд інтерфейсу й приймальне тестування центром.
