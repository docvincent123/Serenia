CI запускається на синтетичних даних, не на фізичному комп'ютері Mark-VI.

## Установка та перевірка на фізичному Linux-комп'ютері

Після об'єднання PR #39 → #40 → #41 і створення актуальної збірки:

```bash
sudo bash deploy/lemvori-care/install.sh
sudo lemvori-carectl diagnose
sudo lemvori-carectl health
sudo lemvori-carectl address
sudo lemvori-carectl list-backups
```

Всі команди діагностики безпечні: не змінюють БД і не виводять медичні дані.
Повну перевірку робочих сценаріїв виконувати лише на окремій копії БД.

## Безпечне відновлення

```bash
sudo lemvori-carectl backup
sudo lemvori-carectl list-backups
sudo lemvori-carectl restore /var/backups/lemvori-care/lemvori-core-YYYYMMDDTHHMMSSZ.dump ВІДНОВИТИ
```

Qt Admin → **Адміністрування → База й копії → Відновити з резервної копії**:
вкажіть шлях до локального архіву (або залиште поле порожнім для останньої стандартної копії)
і вручну введіть `ВІДНОВИТИ`. Далі запитується локальне системне підтвердження (polkit).

Реалізація зупиняє API лише на момент перемикання, створює safety dump і зберігає
попередню базу з окремою назвою. Після переключення перевіряє HTTPS та server_id.
Якщо старт невдалий, повертає попередню базу. При повністю несправному systemd,
TLS чи диску для повторного запуску може знадобитися ручне втручання.

**Правила безпеки:** відновлення дозволено лише з копій саме цього server_id.
Не використовуйте стару копію SOLVIA чи іншого центру. Сеанси після відновлення
недійсні — потрібно ввійти повторно. Операція доступна тільки адміністраторам
на локальному Linux-сервері та вимагає прав root.

### Межі готовності

- Архіви `.dump` зберігаються у каталозі root з правами 0700/0600, **але поки не шифруються**. Перед роботою з реальними медичними даними потрібне шифрування копій, політика зберігання та тест відновлення на іншому носії.
- Потрібна перевірка на конкретному Linux Mint: драйвери, версія PostgreSQL, фактичний LAN IP, правила брандмауера, довіра до сертифікатів на інших ПК.
- Тест на випадок відмови диска/живлення посеред перейменування БД окремо не виконувався; резервні копії треба зберігати поза цим ПК.
- Візуальну приймальну перевірку всіх розмірів моніторів і роботи з реальними елементами вводу треба виконати на робочому ПК після встановлення.
- Ліцензія, документи, медичні згоди та доступи мають бути перевірені відповідальною особою центру до експлуатації.
