# SOLVIA 2.5.1 — окрема консоль та оновлення ПК

## Програми

- **SOLVIA Center**: персональний вхід, працівники, пацієнти, календар, консультації, документи та реквізити центру. Звірка проблемних консультацій із телефонів залишається тут.
- **SOLVIA Server Console**: налаштування підключення сервера, резервні копії, роздача оновлень Windows/Linux/Android та завершення сеансів. Доступ тільки адміністратору.
- **SOLVIA Server**: фоновий API та база даних на серверному ПК. Закриття консолі не зупиняє сервер.

Windows: в інсталяторі можна вибрати тільки робоче місце, тільки Server Console (без PostgreSQL та API) або сервер. Ярлики Center і Server Console окремі.

Linux: для окремої консолі без API/БД виконайте `sudo bash install-client.sh --console`; для обох програм — `sudo bash install-client.sh --with-console`. `solvia-admin-app` — Center, `solvia-server-app` — Server Console. Ярлик «SOLVIA Server» залишається термінальним керуванням службами; кнопка «Служби сервера» в консолі відкриває це меню. Центр і консоль — окремі вікна одного GTK-процесу зі спільним сховищем сеансу. На Windows обидва EXE використовують той самий локальний WebView2-профіль.

## Вхід після оновлення

Чинний токен зберігається для конкретної адреси сервера між закриттям вікна, перезавантаженням та заміною UI. Пароль не зберігається. Center і Server Console на одному ПК використовують цей самий сеанс; другий сеанс на сервері не створюється. Вихід або відкликання токена завершує доступ і в іншому відкритому вікні.

На іншому ПК новий вхід залишається заблокованим, доки чинний сеанс не завершено. Якщо попередня версія вже втратила токен, адміністратор може завершити потрібний сеанс у Server Console або локально на Linux:

```bash
sudo solvia-admin end-sessions admin
```

Замість `admin` вкажіть точний логін. Ця команда не змінює пароль, працівників чи пацієнтів, і не завершує сеанси інших логінів. Вона доступна після оновлення серверного пакета. Для вже встановленої старої версії (кластер SOLVIA на порту 55432):

```bash
sudo -u postgres psql -p 55432 -d solvia -v ON_ERROR_STOP=1 -c "DELETE FROM sessions WHERE user_id IN (SELECT id FROM users WHERE login='admin');"
```

## Роздача оновлень через мережу центру

1. Спочатку один раз встановіть сервер і потрібні ПК-клієнти 2.5.1. Старі клієнти без цього модуля самі не навчаться шукати оновлення.
2. Server Console → **Оновлення ПК**. Оберіть Windows або Linux, фактичну версію пакета, інсталятор та опис змін. Windows — саме EXE-інсталятор, не ZIP з Artifacts; Linux — tar.gz із `install-client.sh`. Максимум 32 МБ.
3. Натисніть **Опублікувати оновлення ПК**. Пакет зберігається на сервері центру. Інтернет на робочих ПК не потрібний.
4. ПК потрібної платформи після входу та приблизно щохвилини перевіряють доступність новішої версії. Порівняння числове: 2.10.0 новіша за 2.9.9. Версію 2.5.1 клієнт 2.5.1 повторно не пропонує.
5. Працівник натискає **Завантажити оновлення**. Клієнт перевіряє розмір і SHA-256, відкриває стандартне збереження файла та показує інструкцію встановлення.
6. Windows: закрити SOLVIA й запустити завантажений EXE поверх наявної програми з тим самим набором компонентів. Linux: розпакувати, закрити SOLVIA та виконати **`sudo bash install-client.sh`** у папці пакета. Це оновлює клієнт без створення сервера чи БД на робочому ПК.

Встановлення виконується працівником/системним адміністратором локально; прихованого віддаленого запуску EXE або скриптів немає. На самому сервері для оновлення API використовуйте серверний інсталятор/`solvia-admin update` з перевіреною копією бази.

**Оновлення Android** у Server Console використовує наявний механізм підписаних APK. **Сеанси пристроїв** дозволяють завершити попередній вхід працівника.

Оновлення ПК можна зняти з роздачі. Файл не видається без автентифікації або після відкликання публікації. Шляхи серверного сховища клієнтам не повертаються. Публікувати й відкликати пакети може тільки адміністратор. Пакети зберігаються незмінними під SHA-256; метадані й журнал публікацій оновлюються транзакційно.
