# Lemvori Care для Linux

Lemvori Care використовує нативні вікна Qt Quick. Обидва застосунки підключаються через HTTPS до тієї самої бази центру через наявний API.

| Застосунок | Роль | Робота |
| --- | --- | --- |
| Lemvori Care · Реєстратура та керівник | Реєстратура | Пошук і створення картки, вибір психолога й кабінету, вільні години, підтвердження запису, перенесення та скасування, прибуття пацієнта, календар і психологи на зміні. |
| Lemvori Care · Реєстратура та керівник | Керівник | Зведення за місяць, стан психологів, перегляд виписок, погодження або повернення з причиною. |
| Lemvori Care Admin | Адміністратор | Працівники й ролі, кабінети, напрямки, зміни, доступ реєстратури, правила запису, дані й файли підключення центру, сеанси, журнал, стан сервера та резервні копії. |

Після встановлення відкрийте потрібний ярлик. На екрані входу натисніть «Підключення». У відкритому вікні введіть HTTPS-адресу або виберіть «Відкрити файл центру» і відкрийте файл `.solvia`. Програма перевіряє TLS і запам’ятовує ідентифікатор сервера. Під час наступного запуску перевірка збереженого підключення починається автоматично. Сертифікат локального CA має бути довіреним у системі. Психологи використовують Android.

Щоб записати пацієнта, відкрийте «Пацієнти», знайдіть картку й натисніть «Записати». Оберіть психолога, кабінет, дату, тривалість і вільний час. Сервер повторно перевірить доступність при підтвердженні.

Вкладка «База та копії» виконує створення та відновлення копій через локальний `solvia-admin` після перевірки прав ОС. На серверному ПК відкрийте Admin з локальною HTTPS-адресою. Для відновлення виберіть `.dump` і введіть «ВІДНОВИТИ».

## Встановлення та перевірка

GitHub Actions **Lemvori Care native desktop** збирає пакет у `lemvori-care-native-linux-x64`. Розпакуйте ZIP і виконайте:

```bash
sudo apt install ./solvia-native_3.2.0~preview5_amd64.deb
```

Пакет встановлює два ярлики та Qt-клієнт для Ubuntu 24.04 amd64 і сумісної бази Linux Mint. Встановлення не мігрує PostgreSQL. Перед використанням у центрі перевірте обидва ярлики, з’єднання з CA, реєстрацію, запис із вибором часу, надходження прийому в Android і рольові обмеження на тестових даних.

Для Windows завантажте `lemvori-care-native-windows-x64` і розпакуйте весь архів в одну папку. Запускайте відповідний `.exe` із цієї папки. На ПК потрібен Microsoft Visual C++ Redistributable x64. Локальні операції з резервними копіями виконуються з Linux-сервера.

Поточний нативний пакет має статус preview. Повна картка з документами, створення сімейних і групових прийомів, черга очікування, супервізії, TV-виклики та офлайн-редагування ПК ще потребують перенесення або перевірки в Qt. Для цих сценаріїв збережіть доступ до наявної програми.

Розробка потребує CMake, компілятора C++20, Qt 6.4+ та модулів QML, перелічених у `.github/workflows/native-qt-linux.yml`.

```bash
cmake -S native/linux -B build/native-linux -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-linux --parallel 2
./build/native-linux/solvia-native
./build/native-linux/solvia-native --admin
```


## Основний напрямок працівника

У **Lemvori Care Admin → Працівники** роль доступу та основний професійний напрямок задаються **окремо**. Адміністратор вибирає напрямок із довідника **Напрямки** (наприклад, «Арттерапія» або «Ерготерапія»). Зміна напрямку сама по собі не розширює права доступу до консультацій, призначень чи документів: сервер продовжує застосовувати чинні ролі `admin`, `reception`, `psychologist`, `director`.

Для сумісності зі старими обліковими записами поле `users.primary_service_code` має порожнє значення за замовчуванням. Сервер приймає лише наявні активні напрями для нових призначень. Відключений напрямок залишається видимим у вже збереженій картці працівника і не знімає роль.

**Порядок розгортання:** спочатку оновити SolviaServer, виконати резервне копіювання та перевірити ідемпотентну міграцію PostgreSQL, після чого встановлювати нові Qt-клієнти. Під час оновлення не видаляйте таблиці користувачів і сеансів. Окремі нові клінічні ролі потребують подальшого проєктування матриці доступу й тестів серверної авторизації.
