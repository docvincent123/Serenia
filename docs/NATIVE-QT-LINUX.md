# SOLVIA Native для Linux (Qt 6 / Qt Quick)

Це справжній Qt Quick/QML + C++ клієнт, **без WebKitGTK, Chromium, HTML чи JavaScript-вебсторінки**.
Backend лишається чинним SolviaServer + PostgreSQL на окремому Linux-сервері.
Дизайн і фірмова золота емблема відповідають SOLVIA; ресурси лого взято з `assets/solvia-mark.svg`.

## Що вже працює у native MVP

- Повністю нативне вікно SOLVIA, логотип/іконка, вхід для admin/reception/director; логін і пароль передаються тільки через HTTPS. Bearer-токен лишається лише в пам'яті процесу, після закриття потрібен новий вхід.
- Налаштування єдиного HTTPS-сервера, перевірка `/api/health`, запам'ятовування URL та `server_id` у QSettings, обов'язкова перевірка TLS без ignoreSslErrors.
- Головна з реальними лічильниками `/api/workday/home`, найближчими прийомами, статусом зміни.
- Календар і оперативні прийоми з API; кнопка «Пацієнт прибув» виконує справжній POST.
- Пошук у каталозі пацієнтів, реєстрація нової картки та створення індивідуального/дитячого/кризового запису до існуючого пацієнта через серверний API.
- Табло психологів зі статусом `busy/waiting/available`, кнопки включення й зняття працівника зі зміни **лише якщо сервер уже має `/api/shift-psychologists` із PR #29**. До оновлення сервера показує чесне повідомлення, а не вигадані статуси.
- Адміністратор може відкрити/закрити зміну. Закриття додатково підтверджується, сервер перевіряє консультації та чернетки.
- Серверний огляд адміністратора (PostgreSQL, диск, SSL), без root-команд із графічного клієнта.
- Підтримка масштабування QML, бічне меню без верхньої шторки «Головна / Прийоми / ...», окрема кнопка «Назад».
- Фонове оновлення стану кожні 15 секунд без локального кешу медичних даних.

## Що поки залишити у перевіреному GTK-клієнті

Це **не є повна функціональна заміна SOLVIA 3.1**. Перш ніж зробити його основним для всіх працівників, перенести й перевірити:
- Повну картку пацієнта, сім'ї, архів, медичні/психологічні звіти, файли, підписи, супервізії.
- Повний сценарій групових/сімейних прийомів, перенесення, скасування, чергу очікування та TV-виклики.
- Системні події/дзвіночок, фонові звуки, контроль оновлень, документи та всі адміністративні майстри.
- Провести перевірку на робочих ПК з реальною мережею і довіреним CA (тільки синтетичні дані).

Жодні пацієнтські дані не мігруються в цей клієнт, і він не встановлює PostgreSQL.

## Збірка Ubuntu 24.04 / Linux Mint на сумісній базі

Потрібні Qt 6.4+, компілятор C++20, CMake:

```bash
sudo apt update
sudo apt install -y cmake ninja-build g++ qt6-base-dev qt6-declarative-dev qt6-svg-dev \
    qml6-module-qtquick qml6-module-qtquick-controls qml6-module-qtquick-layouts \
    qml6-module-qtquick-window qml6-module-qtqml qml6-module-qtqml-models \
            qml6-module-qtquick-templates qml6-module-qtquick-shapes \
            qml6-module-qtqml-workerscript libqt6svg6
cmake -S native/linux -B build/native-linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-linux --parallel 2
./build/native-linux/solvia-native
```

Або `bash native/linux/build-native.sh`. Для тесту без екрану:
`QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software ./build/native-linux/solvia-native --smoke`.

### Звичайний Linux-інсталятор (.deb)

Після успішної GitHub Actions збірки **SOLVIA Native Qt Linux** завантажте artifact
`solvia-native-linux-x64`. У ZIP є перевірений виконуваний файл і
`solvia-native_3.2.0~preview1_amd64.deb`.

```bash
sudo apt install ./solvia-native_3.2.0~preview1_amd64.deb
```

Це встановлює тільки нативний клієнт з іконкою SOLVIA. Ubuntu автоматично
дозавантажить його Qt/QML залежності. Для Ubuntu 24.04 amd64; інші дистрибутиви
потрібно перевіряти окремо. Пакет має внутрішній preview-статус і не є
виробничим релізом. Класичний GTK-клієнт не видаляється.

Інсталяція **лише клієнта**:
```bash
sudo bash native/linux/install-native-client.sh
```

У меню буде **SOLVIA Native** з тією самою жовтою емблемою. Перевірене старе робоче місце не змінюється. **Лише після приймання всіх функцій** можна свідомо замінити основний ярлик:
```bash
sudo bash native/linux/install-native-client.sh --make-default
```
Класичний клієнт лишається окремим ярликом `SOLVIA Classic` — аварійний шлях повернення.

## Мережева безпека та обмеження

1. Довірити внутрішній SOLVIA CA **у системному сховищі Linux**. Не ставити `ignoreSslErrors` і не використовувати `http://`.
2. Вхід виконується працівником щоразу після закриття програми. Адреса сервера не містить пароля.
3. Сервер перевіряє роль на кожному API; UI теж приховує заборонені операції.
4. Перемикання URL скидає сеанс. Під час запиту відповіді попереднього сеансу відкидаються.
5. Файл конфігурації QSettings містить лише server URL і server_id. Медичні записи чи паролі в ньому не зберігаються.
6. Поточний MVP **не має офлайн-редагування** на Linux. Не вводьте дані без доступного сервера; Android зберігає власну синхронізацію.
7. Новий застосунок не вимикає і не змінює `solvia.service`, `solvia-http.service`, `PostgreSQL`, резервні копії чи мережеві правила.

## План перевірки перед основним розгортанням

1. CI Qt/CMake компіляція + offscreen smoke + перевірка відсутності WebKit у лінковці.
2. Під'єднання із перевіреним TLS/CA та із навмисно неправильним сертифікатом, перевірка server_id.
3. Вхід усіх дозволених ролей; відмова психологу в desktop-роли.
4. Прийоми, прибуття, створення пацієнта і запис, відмова сервера при подвійній зайнятості.
5. Розрив з'єднання, перезапуск програми, закриття зміни, відкликання сесії.
6. Склад психологів після встановлення PR #29; UI не мусить показувати «вільний» при відсутньому серверному API.
7. UI 1366×768, 1920×1080 та мінімальні ноутбуки. Порівняння всіх розділів зі старим клієнтом.
