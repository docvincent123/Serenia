# Архітектура SOLVIA 0.1

Windows Win32 + Direct2D client → WinHTTP HTTPS JSON API → C++ server → SQLite WAL.

## Доступ

| Об’єкт | Адміністратор | Реєстратура | Психолог | Керівник |
|---|---|---|---|---|
| Працівники, кабінети | створення, перегляд | кабінети для запису | кабінети для запису | довідник |
| Реєстраційні дані пацієнтів | усі | усі | призначені йому | заборонено |
| Сім’ї | створення, перегляд | створення, перегляд | лише назва сім’ї свого пацієнта | заборонено |
| Календар | усі, створення/перенесення/скасування | усі, створення/перенесення/скасування | власний розклад | лише агрегати |
| Приватні консультації | заборонено | заборонено | свої для призначеного пацієнта | заборонено |
| Результати анкет | заборонено | заборонено | свої для призначеного пацієнта | заборонено |
| Статистика | так | ні | ні | так |
| Аудит без текстів нотаток | так | ні | ні | ні |

Адміністратор не може додати собі роль психолога через запит на пацієнта. Роль береться з бази по серверній сесії. Разом із тим це не захищає від адміністратора ОС/БД — потрібні організаційні правила й шифрування диска.

## Дані

`users`, `sessions`, `patients`, `families`, `rooms`, `appointments`, `attendees`, `consultations`, `assessments`, `audit`. Сімейний зв’язок — не дозвіл читання. Запис зберігає учасників окремою таблицею. Приватні поля не включаються в DTO реєстратора/адміністратора. Керівник не має API списку пацієнтів.

Мутації виконуються у `BEGIN IMMEDIATE`; сервер серіалізує операції mutex. Перевірка конфлікту та вставка — одна транзакція. Повторна консультація за парою запис/пацієнт блокується UNIQUE. У клієнті кнопка збереження заблокована на час запиту, а форма зберігає введені дані при помилці. Після втрати відповіді перевірте таблицю перед повторною дією. Загальної idempotency-key системи поки немає.

Токени сесій/анкет зберігаються в БД у вигляді SHA-256. Клієнт тримає токен сесії тільки в пам’яті. Немає CORS і cookie-авторизації. У сторінці анкети токен передається у fragment, прибирається з адресного рядка, не завантажуються сторонні ресурси. Сервер не веде HTTP access-log з посиланнями. Не поширюйте посилання стороннім.

Час записів локальний, формат `YYYY-MM-DDTHH:MM`, години 08:00–20:00. Сесії й терміни посилань — Unix time. Часовий пояс усіх робочих ПК має відповідати серверу.

## Розширення

`module_settings`: payments, reminders, consents, patient_portal, rehaflow (вимкнені).
`outbox`: подія `appointment.saved` з ID запису для майбутнього сервісу нагадувань. Доставлення, повтори, події скасування та інтеграційний адаптер ще не реалізовані.

Додаткові таблиці оплат, документів та згод слід вводити окремими версійованими міграціями. Поточна схема — перша версія, `CREATE TABLE IF NOT EXISTS`; загальний механізм міграцій ще не потрібен для порожньої БД, але обов’язковий перед змінами схеми.

## Резервування

Для ручної резервної копії зупиніть SolviaServer і скопіюйте всю папку `data` у захищене місце. Відновлення: зупиніть сервер, збережіть поточну папку окремо, поверніть повну копію, запустіть сервер і перевірте дані. Не копіюйте тільки `.db` під час роботи WAL. Автоматичного резервування та перевірки відновлення у MVP немає.
