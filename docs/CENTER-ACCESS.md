# Підключення центру та право користування

Основа: `fix/android-appointment-delivery`, а не застарілий `main`.

## Один файл для Android, Windows і Linux

Server Console → Налаштування → Підключення: збережіть постійне HTTPS DNS-ім’я у Local API URL або VPS API URL. Натисніть «Файл для Android / ПК». На екрані входу ПК/Linux виберіть «Підключити центр із файла»; Android — «Відкрити файл SOLVIA-Mobile.solvia».

Експорт з Console навмисно відхиляє числовий IP: спочатку потрібне DNS-ім’я. Старий `/api/mobile-config` без `stable=1` залишається сумісним з IP-профілями. Профіль v2 містить назву центру, HTTPS-адресу та випадковий `server_id`, але не паролі/токени/медичні дані. TLS залишається обов’язковим. Перевірка ID не замінює перевірку сертифіката.

Щоб той самий файл працював локально і на VPS:

1. Адміністратор налаштовує стабільне DNS-ім’я. Для локальної мережі без інтернету його має обслуговувати локальний DNS. Для зовнішнього доступу — публічний DNS або VPN.
2. Сертифікат повинен відповідати цьому імені; телефони і ПК мають довіряти його видавцю.
3. При переїзді переноситься база разом з `installation_identity`; DNS перемикається на нову адресу. Два незалежні активні сервери з копіями БД не створювати: автоматичної реплікації немає.
4. Без перенесення identity новий сервер потребує нового профілю і перевипуску ліцензії.

Цей реліз не налаштовує DNS, роутер, VPN чи сертифікат автоматично. Файл сам по собі не може знайти довільний сервер у чужій мережі. Профіль v1 підтримується для сумісності, але не перевіряє identity. На Android після зміни сервера стара офлайн-сесія анулюється; чернетки не видаляються.

## Ліцензія видавця

Server Console → Налаштування → Право користування показує ID сервера, статус, строк і дає імпортувати підписаний файл. GET `/api/license` доступний авторизованим працівникам; POST — лише адміністратору. Підпис Ed25519 зв’язує ID сервера, центр, номер ліцензії та строк. Перевірка локальна, інтернет не потрібний.

На захищеній машині видавця (один раз; приватний ключ НЕ передавати центру):

```sh
umask 077
openssl genpkey -algorithm Ed25519 -out publisher-private.pem
openssl pkey -in publisher-private.pem -pubout -out publisher-public.pem
python3 tools/issue-center-license.py --key publisher-private.pem \
  --server-id ID_З_CONSOLE --center 'Назва центру' \
  --expires '2027-10-23T00:00:00+03:00' --output center.solvia-license
```

На сервері встановити тільки відкритий ключ, вказати абсолютний шлях у `SOLVIA_LICENSE_PUBLIC_KEY` для служби SOLVIA та перезапустити службу. Linux: `Environment=SOLVIA_LICENSE_PUBLIC_KEY=/etc/solvia/publisher-public.pem` у systemd override; Windows: змінна оточення процесу служби/завдання. Ключ має бути доступним для читання обліковому запису служби. Потім імпортувати файл у Console.

Без цієї змінної сервер працює в режимі `unmanaged`: оновлення не блокує існуючий центр. З налаштованим ключем і без дійсної ліцензії сервер відхиляє зміни HTTP 402; вхід, вихід, перегляд та поновлення ліцензії залишаються доступними. Старі записи не видаляються. Нові консультації не синхронізуються до поновлення: заплануйте активацію до початку зміни. Це технічний дозвіл, не юридичний договір. Ліміти працівників, білінг та дистанційне відкликання не реалізовано. Адміністратор ОС може змінити оточення/код сервера; цей механізм не є DRM проти власника сервера. Строк залежить від системного годинника.

## Перевірка

Локально пройшли: production-збірка React, тести профілів, 8 перевірок реальних підписів Ed25519 (у тому числі підміна, інший сервер, прострочення), перевірка mobile-security-config, наявні тести drafts/booking/backup-status/pc-updates/performance/shift-workspace.

Зокрема: імпорт файла, оновлення старої БД, ввімкнений/вимкнений дозвіл сповіщень, заблокований екран, перезавантаження телефона, зміна IP за незмінного DNS, повторна активація. Нові CTest і API сценарії включено в репозиторій. Не заявляємо, що всі баги або затримки Android усунені.
