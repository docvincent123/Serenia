# Захищене сховище центру

Ці інструменти підготовлені для виконання на Linux-сервері центру. На робочому сервері вони в цій сесії не запускалися.

Потрібні PostgreSQL, cryptsetup, e2fsprogs і вільне місце. Спочатку створіть і перевірте резервну копію; зміна розміщення робочого PostgreSQL виконується під час обслуговування. Ключ ліцензії Ed25519 та пароль LUKS — різні засоби з різним призначенням.

```bash
sudo install -d -m 0700 /srv/lemvori-storage
sudo bash deployment/create-encrypted-storage.sh \
  /srv/lemvori-storage/center-data.luks /mnt/lemvori-secure 64
```

Обидва кінцеві шляхи мають бути новими. Скрипт відмовляється працювати з наявними файлами, пристроями, символьними посиланнями чи батьківськими каталогами, доступними на запис іншим користувачам. На новому томі створюються папки `postgresql`, `documents`, `backups`.

Після контрольованого перенесення налаштуйте фактичний `data_directory` PostgreSQL, місця вкладень і резервних копій на цей том. Перевірте кожне місце:

```bash
python3 tools/check-encrypted-storage.py \
  /mnt/lemvori-secure/postgresql /mnt/lemvori-secure/documents /mnt/lemvori-secure/backups
```

`luks_verified` означає виявлений LUKS у ланцюжку блокових пристроїв, зокрема під LVM. `unverified` не підтверджує шифрування й не є твердженням про незашифрованість диска хмарного провайдера. Дистанційне сховище PostgreSQL перевіряється на його сервері.

Скрипт не змінює `fstab`, `crypttab`, конфігурацію PostgreSQL, наявні дані чи автозапуск. Збережіть recovery-матеріали та перевірену копію LUKS-заголовка поза цим томом. Після перезавантаження розблокуйте том до старту PostgreSQL; спосіб безпечного автоматичного розблокування залежить від обладнання центру.
