# SOLVIA by QureMed — 0.2.0 React Desktop

Окремий продукт для психологічного реабілітаційного центру. Репозиторій має назву Serenia; назва програми — **SOLVIA**.

## Стек як у rehaflow-final

- **Клієнт Windows:** C++20 Win32 shell + Microsoft Edge WebView2. У WebView2 працює **React 19 + Vite 8** інтерфейс. Electron не використовується.
- **Сервер:** C++20, cpp-httplib, OpenSSL, SQLite у режимі WAL. Працює на ПК центру; дані зберігаються у `data/solvia.db`.
- **Анкета пацієнта:** окрема HTML/JS сторінка, яку віддає сервер за одноразовим посиланням.
- Python використовується лише в автоматизованих API-тестах. Node.js потрібен лише для збірки React. Для запуску готового ZIP Python, Node.js і Docker не потрібні. На Windows потрібен WebView2 Runtime.

## Завантаження та перший запуск

GitHub → **Actions → SOLVIA • Windows build and security tests → успішна збірка → Artifacts → SOLVIA-0.2.0-Windows-x64**. Розпакуйте ZIP у папку з правами на запис (наприклад, `C:\Solvia`).

1. Для тестування виконайте `01-Demo-Setup.bat`: створить 4 ролі та покаже випадкові паролі. Збережіть їх. Для чистого запуску замість цього використайте `01-First-Run.bat`: буде тільки адміністратор.
2. Запустіть `02-Start-Server.bat`, залиште вікно відкритим.
3. Запустіть `03-Open-SOLVIA.bat` або `Solvia.exe`.
4. Сервер за замовчуванням: `http://127.0.0.1:8765`.
5. Увійдіть одним зі створених логінів: `admin`, `reception`, `psychologist`, `director`. Паролі унікальні, у коді їх немає.

Початкові налаштування не перезаписують наявну базу. Для другого й наступних запусків виконуйте лише кроки 2–3.

## Головний сценарій

1. **Адміністратор → Команда:** додайте психолога, реєстратора, керівника (у демо вони вже є). Кабінети створені під час ініціалізації; можна додати свої.
2. **Реєстратура → Пацієнти → Додати пацієнта:** ПІБ, телефон, дата народження, категорія, психолог; сім’я за потреби.
3. **Календар → Вільні години:** оберіть психолога, кабінет, дату.
4. **Новий запис:** оберіть учасника, психолога, кабінет і час. Сервер перевіряє конфлікти психолога, кабінету та пацієнта. Для тестової проведеної консультації можна обрати минулий день.
5. **Психолог → Мої пацієнти → Відкрити картку:** встановіть дату запису над таблицею → Консультація → нотатка, цілі, наступний план, домашнє завдання. Майбутні консультації не завершуються достроково.
6. **Керівник → Огляд центру:** F5 оновлює статистику. Проведена консультація потрапляє у поточний місяць за датою її збереження.

У таблицях працює подвійний клік. F5 оновлює поточну сторінку. Пошук у пацієнтах враховує регістр. На дату в календарі впливає поле `YYYY-MM-DD` і кнопка «Оновити день».

## Можливості MVP

- Авторизація, 8-годинні сесії, вихід з анулюванням токена, PBKDF2-HMAC-SHA256 (600 000 ітерацій), випадкові солі.
- Ролі на сервері; призначений психолог бачить своїх пацієнтів. Адміністратор та реєстратура отримують тільки реєстраційні поля. Керівник отримує зведені показники.
- Створення пацієнтів, сімей та сімейних ролей. Належність до сім’ї не відкриває приватних карток інших її учасників.
- Денний календар, індивідуальні й групові записи, перенесення, скасування, список вільних годинних слотів. Час центру: локальний час сервера; встановіть часовий пояс Windows правильно.
- Група завершується, коли психолог збереже окрему консультацію для кожного учасника. Після першої нотатки її не можна скасувати чи переносити. Учасники мають бути призначені психологу цієї групи.
- Історія приватних консультацій, цілі, план, домашні завдання. Подвійний клік відкриває повний текст.
- Анкета «Самопочуття сьогодні»: призначення психологом, одноразове посилання на 7 днів, заповнення пацієнтом, сума 0–30 та зміна порівняно з попереднім результатом. **Авторський інструмент самоспостереження, не валідована діагностична шкала.**
- Статистика: загальна кількість пацієнтів, нові за місяць, проведені консультації, повторні консультації, скасовані записи, записи й години кожного психолога.
- Журнал дій без текстів нотаток. `outbox` для майбутніх інтеграцій, реєстр вимкнених майбутніх модулів.

## Мережева робота

На інших ПК запустіть `Solvia.exe` та введіть HTTPS-адресу сервера. Наприклад:

```powershell
.\SolviaServer.exe --host 0.0.0.0 --port 8765 --cert C:\Solvia\tls\server.pem --key C:\Solvia\tls\server.key
$env:SOLVIA_API = 'https://solvia.center.local:8765'
.\Solvia.exe
```

Потрібен сертифікат з іменем сервера, якому довіряє Windows кожного клієнта. Не вимикайте перевірку сертифіката. Дозвольте TCP 8765 лише у приватній мережі центру. Без сертифіката сервер дозволяє роботу тільки через loopback. Посилання на анкету працює з інших пристроїв тільки з мережевою адресою і довіреним сертифікатом. Налаштування DNS/сертифіката не автоматизоване.

## Межі версії та наступні кроки

Це перший MVP для перевірки на синтетичних даних. Перед роботою з реальними приватними записами потрібні перевірка в центрі, модель згод/опікунства для дітей, політика доступів/зберігання, налаштування резервування та захист диска. SQLite не шифрує файл: адміністратор ОС із доступом до файлів може читати його поза програмою.

Поки **не реалізовано:** оплати й пакети, SMS/Telegram/push, документи та юридичні згоди, повний мобільний кабінет, стандартизовані шкали, інтеграцію RehaFlow, інсталятор, самовідновлення пароля, редагування/деактивацію працівників, передачу пацієнта іншому психологу, адаптивний мобільний клієнт. Під ці модулі залишені точки розширення, а не імітація їх роботи.

Клієнт: Windows 10/11 x64 + WebView2 Runtime, робоча область від 980×650. React-екрани оновлюють дані після робочих дій; календар і звіти мають явне оновлення. Записи консультацій у MVP незмінні; виправлення та версіонування — наступний етап.

## Збірка з коду

Visual Studio 2022 (Desktop development with C++), CMake ≥3.24, vcpkg, Node.js 22+, npm. Для тестів Python 3.11+.

```powershell
npm install --prefix frontend
npm run build --prefix frontend
cmake -S . -B build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-solvia -DVCPKG_OVERLAY_TRIPLETS=cmake/triplets -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
New-Item -ItemType Directory -Force build/Release/ui | Out-Null
Copy-Item frontend/dist/* build/Release/ui/ -Recurse -Force
```

Результат: `build/Release/Solvia.exe`, `build/Release/SolviaServer.exe` і `build/Release/ui/`.
