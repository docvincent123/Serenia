# SOLVIA by QureMed — 0.3.0

SOLVIA — локальна система для приватного психологічного реабілітаційного центру. Репозиторій має назву Serenia; назва продукту в інтерфейсі — **SOLVIA by QureMed**.

## Архітектура

- **Серверний ПК Windows:** PostgreSQL 17 + `SolviaServer.exe` + Caddy HTTPS + `Solvia.exe`.
- **Desktop:** C++20 Win32/WebView2 shell, всередині — React 19 + Vite. Electron не використовується.
- **Android:** окремий APK для психологів/персоналу. Підключається до серверного ПК тільки через HTTPS у локальній Wi-Fi/LAN мережі центру.
- **Одна база:** desktop і Android працюють з одним SOLVIA API та однією PostgreSQL базою. Мобільний пристрій ніколи не підключається до PostgreSQL напряму.
- **PostgreSQL:** слухає тільки localhost. У локальну мережу SOLVIA відкривається тільки HTTPS порт 8443 через Caddy. RehaFlow може одночасно використовувати 443.
- **Без Docker:** для звичайного серверного ПК Docker, Python і Node.js не потрібні.

## Встановлення серверного ПК

З GitHub Actions завантажте artifact **SOLVIA-0.3.0-Setup-EXE** і запустіть Setup EXE від імені адміністратора.

Інсталятор:
1. встановлює PostgreSQL 17, якщо його ще немає;
2. створює окремого користувача БД `solvia` та базу `solvia`;
3. просить створити **власний логін і пароль** першого адміністратора SOLVIA;
4. автоматично визначає IPv4 серверного ПК у Wi-Fi/Ethernet мережі центру;
5. встановлює локальний HTTPS через Caddy;
6. відкриває у Windows Firewall тільки TCP 8443 для `LocalSubnet` у Private profile;
7. реєструє `SOLVIA Local Server` у Windows Task Scheduler для автозапуску після перезавантаження;
8. створює локальний CA та копіює `QureMed-Local-CA.crt` у папку SOLVIA.

Конфігурація сервера зберігається у `C:\ProgramData\QureMed\SOLVIA\server.env` з обмеженими ACL. Логін/пароль першого адміністратора передаються серверу тільки під час первинної ініціалізації; пароль у відкритому вигляді після створення адміністратора не зберігається.

Після встановлення буде показана адреса виду:

`https://192.168.1.100:8443`

Це адреса, яку потрібно ввести в Android-застосунку на пристроях, підключених до Wi-Fi центру.

## Ролі

**Адміністратор** має desktop-доступ до керування системою, працівниками, кабінетами, календарем, пацієнтами, статистикою, записами консультацій психологів, звітами за зміну та audit log. У розділі «Команда центру» він створює працівників, задає ролі, змінює роль, вмикає/вимикає доступ і скидає пароль. Останнього активного адміністратора вимкнути або понизити в ролі не можна.

**Реєстратура** працює переважно на ПК: створює пацієнтів і сім’ї, веде календар, записує до психолога, переносить/скасовує записи. Реєстратура не отримує приватні нотатки психологів.

**Психолог** працює переважно з Android-планшета/телефона: бачить власний календар, лише своїх пацієнтів, картку пацієнта, консультації, нотатки, цілі, план наступної зустрічі, домашні завдання та анкети. Наприкінці зміни заповнює підсумковий звіт; кількість проведених консультацій підтягується автоматично.

**Керівник центру** бачить агреговану статистику без приватних психологічних записів.

## Android

GitHub Actions створює artifact **SOLVIA-Android-test-APK**.

Перший запуск:
1. підключіть планшет/телефон до Wi-Fi центру;
2. встановіть `QureMed-Local-CA.crt` із серверного ПК як довірений CA-сертифікат Android;
3. відкрийте SOLVIA;
4. введіть `https://<IP серверного ПК>:8443`;
5. після успішного підключення адреса запам’ятовується.

Android-клієнт:
- не дозволяє HTTP;
- не ігнорує TLS-помилки;
- блокує сторонні origin;
- використовує `FLAG_SECURE` проти звичайних скріншотів/запису екрана;
- працює з тим самим React UI, оптимізованим під телефон і планшет.

Якщо IP серверного ПК змінився, на сервері запустіть `installer\Repair-Network.ps1` від адміністратора, після чого введіть нову адресу в Android.

## Головний сценарій

Реєстратор створює пацієнта → записує його до психолога → психолог у Android бачить запис → відкриває картку → додає консультацію та приватну нотатку → керівник бачить збільшення агрегованої статистики.

Записи консультацій доступні психологу-власнику та адміністратору в режимі контролю. Реєстратура і керівник центру не отримують текстів консультацій через API.

## Безпека

- PBKDF2-HMAC-SHA256, 600 000 ітерацій, випадкова сіль.
- Bearer-сесії на 8 годин; токени в БД зберігаються як SHA-256.
- RBAC перевіряється C++ сервером, а не лише React-інтерфейсом.
- Психолог додатково обмежений призначеними йому пацієнтами.
- PostgreSQL не доступний з LAN.
- У LAN для SOLVIA відкритий лише HTTPS/8443 для локальної підмережі; RehaFlow може окремо працювати на 443.
- Android не має bypass TLS.
- Audit log не містить текстів консультацій. Самі консультації та звіти за зміну зберігаються в PostgreSQL і доступні адміністратору за роллю.

Для реального центру додатково потрібні BitLocker/шифрування диска серверного ПК, регулярні резервні копії PostgreSQL, окремі Windows-акаунти та внутрішня політика доступу.

## Розробка

Для Windows build потрібні Visual Studio 2022 C++, CMake, vcpkg, Node.js 22 та WebView2 SDK. Сервер використовує `libpq`, OpenSSL, cpp-httplib і nlohmann-json.

React:

```powershell
npm --prefix frontend install
npm --prefix frontend run build
```

Windows:

```powershell
cmake -S . -B build -A x64 -DCMAKE_TOOLCHAIN_FILE=C:/vcpkg/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-solvia -DVCPKG_OVERLAY_TRIPLETS=cmake/triplets
cmake --build build --config Release --parallel
```

Android:

```bash
cd android
gradle :app:assembleDebug
```
